# Architecture

The distributable has two layers:

1. An Inno Setup bootstrapper installs the self-contained manager, the pinned RNNoise VST2 DLL, the project-built statically linked WebRTC APM VST2 DLL, and the project-built echo cancellation APO (`apo\ncs_aec_apo.dll`, COM-registered by setup). If Equalizer APO is absent, it silently runs the bundled, unmodified 1.4.2 x64 installer. A different installed Equalizer APO version causes a fail-closed stop rather than an implicit downgrade.
2. `NoiseCancellingStack.Manager.exe` owns configuration, capture-endpoint registration, repair, status, and rollback.

For each endpoint, the manager selects LFX/GFX, SFX/MFX, or SFX/EFX using the same rules as Equalizer APO 1.4.2: legacy slots are retained only for legacy-only drivers, combined Bluetooth endpoints use SFX/MFX, and other modern endpoints use SFX/EFX. Capture endpoints receive only the pre-mix APO.

The main Equalizer APO config gets a marked include block. Inside `stage == "capture"`, exactly 48 kHz routes exclusively to RNNoise and exactly 16 kHz routes exclusively to WebRTC APM; every unsupported rate is pass-through. Equalizer APO instantiates the mono VST per selected channel, allowing `Channel: all` without relying on a fixed stereo layout.

The WebRTC plug-in adapts arbitrary callback sizes to mono 160-sample frames and advertises a fixed 160-sample (10 ms) delay. WebRTC is configured for high noise suppression only: echo cancellation, both gain controllers, high-pass filtering, and transient suppression remain disabled. Any processing failure permanently switches that instance to correctly delayed dry audio.

## Echo cancellation (Windows 11)

The echo canceller is a capture mode effect (MFX). Windows runs capture effects from the device outward (EFX, then MFX, then SFX), so it processes microphone audio before Equalizer APO's pre-mix SFX applies noise suppression. Because it implements `IApoAcousticEchoCancellation2`, `IApoAuxiliaryInputConfiguration`, and `IApoAuxiliaryInputRT`, the audio engine attaches a loopback reference of the active render endpoint as an auxiliary input and switches it when the default output changes. The APO asks for 32-bit float at a WebRTC-native rate with at most two channels, and requests post-volume loopback where the endpoint supports it.

`AcceptInput` runs on the engine's loopback thread and only writes the reference into a single-producer/single-consumer ring. `APOProcess` drains complete 10 ms reference blocks (dropping backlog beyond 250 ms), feeds them to WebRTC AEC3, and then processes the 10 ms microphone block in place. AEC3 runs at up to 48 kHz internally with multichannel capture and render; noise suppression and gain control stay off. Its block framing and band-split filter bank add a fixed 128/260/430-frame delay at 16/32/48 kHz, which the APO reports through `GetLatency` and mirrors in a delayed-dry fallback path. A second reviewed patch removes WebRTC's render-path mutex, as the first did for capture; both are safe because each APM instance is driven by one thread at a time.

The manager attaches the APO only on Windows 11, only after confirming its COM and APO registration at the installed path, and only to SFX/EFX endpoints whose MFX value, MFX mode list, and composite MFX list are unused and whose form factor is not headset or handset. It writes the MFX CLSID and a default-mode-only MFX mode list within the same write-ahead journal entry as the Equalizer APO attachment. Endpoints already managed by an earlier version receive it as a separate journaled sub-transaction; the MFX mode list is an optional journal value, so earlier journals stay valid. Endpoints whose Equalizer APO attachment predates the manager receive an echo-canceller-only journal record (`EchoCancellerOnly`) that owns exactly the MFX value and MFX mode list and no child record; it is eligible only when Equalizer APO occupies the SFX slot alone, so noise suppression still follows echo cancellation. If another tool later rewrites that slot and none of the record's values remain, repair drops the record instead of reporting a permanent conflict.

Chromium opens capture streams with `AUDCLNT_STREAMOPTIONS_RAW` whenever the endpoint's `RawProcessingSupported` property is true, and raw streams skip every SFX, MFX, and EFX. After the endpoint pass, install and repair reconcile two journaled Properties values on every managed endpoint with a noise-suppressed sample rate: the device description gains ` FILTERED`, and `RawProcessingSupported` is set to `VARIANT_FALSE`. Both take effect for applications immediately. The Audio Endpoint Builder rewrites `RawProcessingSupported` from the driver on every endpoint rebuild (replug, service start, boot), and a value placed in FxProperties is ignored, so the SYSTEM task `Keep microphones filtered` runs `NoiseCancellingStack.Manager.exe watch`. It waits on `RegNotifyChangeKeyValue` below the capture root (with a one-minute safety scan) and re-applies the journaled value wherever Windows has restored the driver's original. It never takes the operation mutex; setup ends it before replacing files and uninstall ends it before rollback. `HKLM\SOFTWARE\NoiseCancellingStack\DisableEchoCancellation` makes the APO pass audio through unchanged at runtime.

## Validation and repair

Before install or repair mutates configuration or endpoint state, the manager verifies all three native SHA-256 digests and invokes the WebRTC DLL's and the echo canceller's synthetic self-test exports. The DLL statically links WebRTC, Abseil, and the Microsoft runtime; its only dynamic dependencies are Windows system libraries. The existing hidden SYSTEM task performs the same fail-closed, idempotent repair one minute after boot.

The endpoint state journal records original and intended-installed values before mutation. Repair is idempotent. Uninstall restores a value only when its current value still equals either the product's installed value or the original value; third-party changes are reported and retained.
